# Architecture

## Document model

A design is a Y.Doc with `meta`, `pageOrder`, `pages` and `elements` maps, plus `assets`, which holds image bytes so a design is complete on its own. The code is in `apps/editor/src/doc`.

`DesignDoc` keeps an immutable snapshot for React and routes every local edit through one transaction origin. That single origin drives undo, persistence (y-indexeddb) and collaboration from the same data.

Video bytes are the exception. They live in their own IndexedDB store so version history and live sync stay small, and the design keeps a poster frame.

## Rendering

Rendering is SVG. The same `PageView` draws the canvas, thumbnails, Present mode and the exports. For export it is rendered to a string with fonts and images inlined, then rasterised. Text has its own line layout (`apps/editor/src/text`), so the screen, PNG, SVG and PDF all break lines in the same place.

Interaction lives in an HTML overlay above each page.

## Sharing

One link, no accounts. Changes travel two ways at once:

- Peer to peer over WebRTC (`collab/peerProvider.ts`), which carries cursors and names.
- Through an end to end encrypted relay (`collab/relayProvider.ts`), so changes arrive even when nobody else is online or WebRTC cannot connect.

The link carries a random key after the `#`, which browsers never send anywhere. The browser derives two things from it with HKDF: a room ID that names the room on the relay, and an AES-GCM key that never leaves the device. Every Yjs update is sealed with that key before upload, so the relay stores and fans out ciphertext it cannot read. Clients compact the log by uploading an encrypted full snapshot.

Limits: 2 MB per message (larger updates are split, see `relayChunks.ts`), 50 MB per room, rooms deleted after 90 days idle. Stop sharing deletes the room.

The relay is a Cloudflare Worker with a Durable Object per room, in [`sync/`](../sync). Its README has the wire protocol, deploy steps and tests.

## Templates

Templates are source files, not data. `apps/editor/templates/vibes/*.mjs` describe them with the helpers in `kit.mjs`, and `scripts/build-templates.mjs` validates them and writes the packs the editor loads. See [apps/editor/templates/BUILDING.md](../apps/editor/templates/BUILDING.md).

## The public site

opentempl.org serves the editor. The guides, template pages, prompt gallery, sitemap and `llms.txt` are static pages generated by `seo/build.mjs` into `apps/editor/public/`, which the Vercel build runs before the editor build.

## Other pieces

- `stats/`: the anonymous counter and email list, a Cloudflare Worker with D1. See [PRIVACY.md](PRIVACY.md).
- `api/`: a Vercel function that proxies Unsplash so the key stays on the server.
- `apps/desktop/`: an Electron shell that packages the built editor.
